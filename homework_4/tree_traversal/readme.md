Решение:

Сначала создаем бинарное дерево поиска.
Каждый узел Node хранит значение value и две ссылки: left и right.
В левом поддереве находятся меньшие значения, в правом — большие. Корень дерева хранится в root.
Вставка работает через рекурсию.
Если дошли до пустого места (node равен None), создаем новый узел.
Если новое число меньше текущего, вызываем вставку для левого поддерева. Если больше — для правого.
После этого возвращаем текущий узел. Так связи между узлами сохраняются.
Одинаковые числа повторно не добавляем. В условии это не оговорено, поэтому используется дерево без дубликатов.
Обходы тоже написаны через рекурсию.
Для каждого обхода создаем пустой список result.
Функция walk получает узел. Если узла нет, заканчиваем вызов. Если узел есть, добавляем его значение в результат и вызываем walk для дочерних узлов в нужном порядке.
Разница между обходами только в очередности действий:

preorder: узел -> левое -> правое
inorder: левое -> узел -> правое
postorder: левое -> правое -> узел
reverse preorder: узел -> правое -> левое
reverse inorder: правое -> узел -> левое
reverse postorder: правое -> левое -> узел

Здесь «узел» означает добавление node.value в result.

В обратных обходах меняем местами левое и правое поддеревья, а не просто разворачиваем готовый список.

Для BST inorder возвращает значения по возрастанию, reverse inorder — по убыванию.


Оценка сложности:

Пусть n — количество узлов, h — высота дерева.

Вставка одного значения занимает O(h), потому что идем от корня только в одном направлении на каждом уровне.
В сбалансированном по высоте дереве это O(log n). Если дерево вытянулось в цепочку, в худшем случае получаем O(n).
Дополнительная память вставки — O(h), потому что при рекурсии сохраняются вызовы функции. Новый узел занимает O(1) памяти.
Построение дерева из n значений последовательными вставками в худшем случае занимает O(n²). Само дерево хранит n узлов и занимает O(n) памяти.
Любой из шести обходов занимает O(n) времени, потому что каждый узел посещаем один раз.
Список result содержит n элементов, поэтому на ответ тратится O(n) памяти.
Рекурсивные вызовы дополнительно занимают O(h) памяти. Итого с учетом ответа — O(n + h), то есть O(n).
Если считать только память сверх возвращаемого списка, получится O(h).
В Python глубина рекурсии ограничена, поэтому на очень длинной цепочке узлов может возникнуть RecursionError.


Визуализация работы алгоритма:

Первый пример:

Вставляем числа:

4 2 6 1 3 5 7

Получаем дерево:

        4
       / \
      2   6
     / \ / \
    1  3 5  7

Сначала вставляется 4, поэтому оно становится корнем.

2 меньше 4 - идет влево. 6 больше 4 — идет вправо.

1 меньше 4 и 2, поэтому становится левым ребенком 2.

3 меньше 4, но больше 2, поэтому становится правым ребенком 2.

5 больше 4, но меньше 6, поэтому становится левым ребенком 6.

7 больше 4 и 6, поэтому становится правым ребенком 6.

Результаты обходов:

preorder: [4, 2, 1, 3, 6, 5, 7]
inorder: [1, 2, 3, 4, 5, 6, 7]
postorder: [1, 3, 2, 5, 7, 6, 4]
reverse preorder: [4, 6, 7, 5, 2, 3, 1]
reverse inorder: [7, 6, 5, 4, 3, 2, 1]
reverse postorder: [7, 5, 6, 3, 1, 2, 4]

Например, preorder начинается с корня 4, затем обходит левую часть 2, 1, 3, а после этого правую 6, 5, 7.

А postorder сначала обходит оба поддерева и только потом добавляет корень 4.


Второй пример:

Вставляем числа:

5 2 8 1 4 3 9

Получаем несимметричное дерево:

        5
       / \
      2   8
     / \   \
    1   4   9
       /
      3

Результаты обходов:

preorder: [5, 2, 1, 4, 3, 8, 9]
inorder: [1, 2, 3, 4, 5, 8, 9]
postorder: [1, 3, 4, 2, 9, 8, 5]
reverse preorder: [5, 8, 9, 2, 4, 3, 1]
reverse inorder: [9, 8, 5, 4, 3, 2, 1]
reverse postorder: [9, 8, 3, 4, 1, 2, 5]

На этом примере особенно видно, что порядок обхода зависит от того, когда добавляем значение узла и какое поддерево обходим первым.


Тесты:

Проверяются несколько разных случаев:
пустое дерево — все шесть обходов возвращают пустые списки;
дерево из одного узла;
обычное дерево из семи узлов — проверяются все шесть обходов;
несимметричное дерев — проверяются все шесть обходов;
дерево только с левыми дочерними узлами;
дерево только с правыми дочерними узлами;
вставка повторяющихся значений;
отрицательные числа и ноль;
вставка нового узла после первого обхода;
проверка, что обходы не изменяют дерево.
