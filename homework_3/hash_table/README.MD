Решение:

Для хранения данных используется только list.

Таблица представляет собой список корзин:

table = [[], [], [], ...]

Каждая корзина тоже является списком.

Внутри корзины хранятся пары ключ-значение в виде списков:

[key, value]

Для каждого ключа вычисляется индекс корзины:

index = hash(key) % capacity

После этого работа происходит только с выбранной корзиной.


Коллизии:

Коллизия возникает, когда разные ключи получают одинаковый индекс.

Для разрешения коллизий используется метод цепочек.

Если несколько ключей попали в одну корзину, они хранятся в одном списке:

table[index] = [
    [key1, value1],
    [key2, value2],
    [key3, value3]
]

При поиске нужного ключа просматривается только эта корзина.


Вставка:

Сначала вычисляется индекс корзины.

Если ключ уже находится в корзине, его значение обновляется.

Если ключа еще нет, в корзину добавляется новая пара:

[key, value]

Перед добавлением нового элемента проверяется заполненность таблицы.

Если после вставки коэффициент заполнения станет больше 0.75, размер таблицы увеличивается в два раза.


Увеличение таблицы:

При увеличении таблицы старый список корзин заменяется новым списком в два раза большего размера.

После изменения capacity индексы ключей могут измениться, потому что индекс вычисляется так:

hash(key) % capacity

Поэтому все старые элементы заново добавляются в новую таблицу.


Поиск:

Для ключа вычисляется индекс корзины.

После этого элементы выбранной корзины просматриваются по одному.

Если ключ найден, возвращается его значение.

Если ключа нет, вызывается KeyError.


Удаление:

Для ключа вычисляется индекс корзины.

После этого ключ ищется внутри выбранной корзины.

Если ключ найден, соответствующая пара удаляется из списка.

Если ключа нет, функция возвращает False.


Оценка сложности:

В среднем вставка, поиск и удаление работают за O(1), если элементы распределены по корзинам достаточно равномерно.

При большом количестве коллизий несколько элементов могут оказаться в одной корзине. Тогда в худшем случае вставка, поиск или удаление могут занять O(n).

Увеличение таблицы занимает O(n), потому что все элементы нужно перенести в новый список корзин.

Операция увеличения выполняется не при каждой вставке, поэтому средняя стоимость последовательности вставок остается близкой к O(1) на одну вставку.

Пространственная сложность - O(n), потому что таблица хранит все добавленные пары ключ-значение.


Визуализация работы алгоритма:

Пусть начальный размер таблицы равен 4.

В начале:

table = [
    [],
    [],
    [],
    []
]

Добавляем пару:

"a" -> 10

Вычисляем:

index = hash("a") % 4

Пусть получился индекс 1.

Тогда:

table = [
    [],
    [["a", 10]],
    [],
    []
]


Теперь добавляем другой ключ, который получил тот же индекс:

"b" -> 20

Получилась коллизия.

Оба элемента сохраняются в одной корзине:

table = [
    [],
    [["a", 10], ["b", 20]],
    [],
    []
]


Поиск ключа "b":

Сначала снова вычисляется индекс:

index = hash("b") % 4

Получаем корзину с индексом 1.

Просматриваем ее элементы:

["a", 10] - ключ не подходит

["b", 20] - ключ найден

Возвращаем значение 20.


Удаление ключа "a":

Находим ту же корзину.

Удаляем список:

["a", 10]

После удаления:

table = [
    [],
    [["b", 20]],
    [],
    []
]


Если таблица становится слишком заполненной, capacity увеличивается в два раза.

Например:

capacity = 4

становится:

capacity = 8

Создается новый список из 8 корзин, после чего все существующие пары заново распределяются по таблице.


Тесты:

Проверяются несколько разных случаев:

вставка элемента и поиск по ключу;

обновление значения существующего ключа;

удаление существующего ключа;

удаление отсутствующего ключа;

поиск отсутствующего ключа;

несколько ключей с одинаковым хешем;

удаление элемента из цепочки коллизий;

увеличение таблицы при заполнении;

сохранение всех элементов после увеличения таблицы;

значения разных типов;

нулевой и отрицательный ключ;

проверка некорректного начального размера таблицы.
