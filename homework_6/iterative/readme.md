Решение:

Реализованы две итеративные сортировки: merge sort и quick sort.
В отличие от предыдущей задачи рекурсия не используется.
Обе функции возвращают новый отсортированный список. Исходный список не меняется.

Merge sort:

Сначала создаем копию массива.

В переменной width храним размер уже отсортированных частей. Сначала width = 1, потому что каждый отдельный элемент уже отсортирован.

В цикле объединяем соседние части по width элементов в одну отсортированную часть.
При объединении сравниваем очередные элементы левой и правой частей и добавляем меньший в результат.
Когда одна часть закончилась, добавляем оставшиеся элементы другой части.

После каждого прохода увеличиваем width в два раза.
Повторяем, пока размер отсортированных частей не станет не меньше длины всего массива.

Quick sort:

Сначала создаем копию массива.

Вместо рекурсивных вызовов используем обычный список stack.
В нем храним пары индексов (left, right), между которыми еще нужно отсортировать элементы.

Берем очередной диапазон из stack.
Если в нем не больше одного элемента, ничего делать не нужно.

Иначе выбираем последний элемент диапазона как pivot.
Перемещаем все элементы не больше pivot в левую часть диапазона, а затем ставим pivot на его место.

После этого добавляем в stack два оставшихся диапазона: слева и справа от pivot.
Повторяем, пока stack не опустеет.

Так мы делаем те же действия, что и в рекурсивном quick sort, но управляем необработанными частями массива сами.


Оценка сложности:

Merge sort:

Временная сложность - O(n log n).
За один проход объединяются все элементы массива, то есть требуется O(n) действий.
Размер частей на каждом проходе увеличивается в два раза, поэтому проходов примерно log n.

Дополнительная память - O(n), потому что создаются копия массива, новый список для слияния и временные части массива.
Рекурсивного стека нет.

Quick sort:

Средняя временная сложность - O(n log n), когда pivot делит диапазоны на достаточно равные части.
Худшая временная сложность - O(n²), когда pivot каждый раз оказывается самым маленьким или самым большим числом.
Например, так получается для уже отсортированного массива при выборе последнего элемента как pivot.

Дополнительная память - O(n), потому что создается копия исходного массива.
Вместо рекурсии используется stack с диапазонами. Он в среднем занимает O(log n) памяти, в худшем случае может занимать O(n).


Визуализация работы алгоритмов:

Возьмем массив:

[4, 1, 3, 2]

Merge sort:

В начале width = 1.
Сливаем соседние части по одному элементу:

[4] + [1] -> [1, 4]
[3] + [2] -> [2, 3]

После первого прохода массив:

[1, 4, 2, 3]

Теперь width = 2.
Сливаем две соседние отсортированные части по два элемента:

[1, 4] + [2, 3] -> [1, 2, 3, 4]

Теперь width = 4. Массив целиком отсортирован.

Ответ:

[1, 2, 3, 4]

Quick sort:

Исходный массив:

[4, 1, 3, 2]

В начале stack:

[(0, 3)]

Берем диапазон от индекса 0 до 3.
Выбираем pivot = 2.
Переставляем элементы так, чтобы меньшие или равные pivot оказались слева, а большие - справа.

После разбиения:

[1, 2, 3, 4]

Pivot = 2 стоит на индексе 1 и больше не двигается.
В stack добавляем оставшиеся диапазоны:

(0, 0) и (2, 3)

В диапазоне (0, 0) всего один элемент, его сортировать не нужно.
В диапазоне (2, 3) рассматриваем [3, 4] и выбираем pivot = 4.
Элементы уже стоят правильно.

Теперь необработанных диапазонов нет, stack пуст.

Ответ:

[1, 2, 3, 4]


Тесты:
Проверяются несколько случаев для обеих реализаций:
обычный массив из нескольких чисел;
пустой список;
один элемент;
два элемента;
уже отсортированный список;
обратный порядок;
одинаковые значения;
повторяющиеся значения;
отрицательные числа и ноль;
массив с несколькими нулями;
проверка, что исходный список не изменяется;
случайный массив;
длинный отсортированный массив;
длинный массив в обратном порядке;
длинный массив из одинаковых элементов;
несколько случайных коротких массивов с повторениями.
