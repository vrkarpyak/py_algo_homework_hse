Решение:

Реализованы две рекурсивные сортировки: merge sort и quick sort.
Обе функции принимают список чисел и возвращают новый отсортированный список. Исходный список не изменяется.

Merge sort:
Если в списке 0 или 1 элемент, возвращаем его копию.
Иначе делим список пополам и рекурсивно сортируем обе половины.
После этого объединяем две отсортированные половины.

При объединении сравниваем первые еще не использованные элементы левой и правой частей.
Меньший элемент добавляем в результат и сдвигаем соответствующий индекс.
Когда одна часть заканчивается, добавляем оставшиеся элементы другой части.

Quick sort:
Сначала делаем копию списка, чтобы не менять исходные данные.
В качестве опорного элемента (pivot) берем последний элемент рассматриваемой части.
Проходим эту часть и переносим все числа, не превосходящие pivot, влево.
Потом ставим pivot между левой и правой частями.
Рекурсивно сортируем части слева и справа от pivot.

Декоратор timer:
Перед вызовом функции запоминаем время с помощью perf_counter().
После завершения функции снова получаем время и выводим разницу в секундах.
Результат функции возвращается без изменений.
Время измеряется только для всего вызова сортировки, а не для каждого шага рекурсии.

Для сравнения берутся четыре массива одинаковой длины: случайный, отсортированный, обратный и с одинаковыми числами.
У quick sort с последним элементом в качестве pivot отсортированный, обратный и одинаковый массивы приводят к неудачным разделениям. В этих случаях quick sort обычно заметно медленнее merge sort.

Оценка сложности:
Merge sort:
Временная сложность - O(n log n), потому что список делится пополам примерно log n раз, а на каждом уровне рекурсии слияние всех частей требует O(n) действий.
Дополнительная память - O(n), потому что создаются новые списки для частей массива и результата. Дополнительно рекурсия использует O(log n) памяти.

Quick sort:
Средняя временная сложность - O(n log n), если опорный элемент делит массив на части разумного размера.
Худшая временная сложность - O(n²), если pivot каждый раз оказывается крайним элементом по величине. Например, при отсортированном массиве и выборе последнего элемента как pivot.
Дополнительная память - O(n), потому что сначала создается копия массива. Само разбиение выполняется без дополнительных списков. Рекурсия использует O(log n) памяти в среднем и O(n) в худшем случае.

Декоратор timer добавляет только фиксированное количество операций и переменных для каждого измерения. Само измерение не меняет асимптотическую сложность сортировок.

Визуализация работы алгоритмов:

Возьмем массив:

[4, 1, 3, 2]

Merge sort:

Сначала делим список:

[4, 1, 3, 2]
   /       \
[4, 1]    [3, 2]
 /   \      /   \
[4] [1]   [3]   [2]

Сливаем отсортированные половины:

[4] + [1] -> [1, 4]
[3] + [2] -> [2, 3]

[1, 4] + [2, 3] -> [1, 2, 3, 4]

Quick sort:

Начальный список:

[4, 1, 3, 2]

Выбираем pivot = 2.
Перемещаем числа, не превосходящие 2, влево, а затем ставим 2 на свое место:

[1, 2, 3, 4]

Слева остается [1], справа [3, 4].
Обе части сортируем рекурсивно.

В итоге получаем:

[1, 2, 3, 4]

Сравнение времени:

Для случайного массива quick sort обычно делит данные достаточно равномерно, поэтому время работы двух сортировок может быть близким.
Для уже отсортированного и обратного массива quick sort с последним pivot выполняет гораздо больше сравнений, чем merge sort.
Если все числа одинаковые, quick sort в этой реализации тоже делает неудачные разбиения.

Точное время зависит от компьютера и текущей нагрузки. Поэтому сравниваем измерения, но не требуем от них конкретного соотношения в тестах.

Тесты:

Проверяются несколько случаев:
обычный массив из нескольких чисел;
пустой список;
один элемент;
два элемента;
уже отсортированный список;
обратный порядок;
одинаковые значения;
повторяющиеся значения;
отрицательные числа и ноль;
отсутствие изменений исходного списка;
случайный массив;
длинный отсортированный массив;
длинный массив из одинаковых чисел;
возврат значения и вывод времени декоратором.
