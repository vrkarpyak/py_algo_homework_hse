Решение:

Реализуем AVL-дерево. Это бинарное дерево поиска, которое после вставки или удаления сохраняет баланс по высоте.

В каждом узле храним значение, ссылки на левого и правого ребёнка и высоту поддерева:

value
left
right
height

Для любого узла все значения в левом поддереве меньше его значения, а в правом поддереве — больше.
Кроме того, разница высот левого и правого поддеревьев должна быть не больше 1.
Высота пустого поддерева равна 0, высота листа равна 1.
При вставке идём по дереву, как в обычном BST:
Если новое значение меньше текущего, идём влево.
Если больше, идём вправо.
Если значение уже есть, повторно его не добавляем.
Когда находим пустое место, создаём новый узел. Затем при возвращении из рекурсии обновляем высоты узлов и, если нужно, выполняем повороты.

Разница высот вычисляется так :
height(left) - height(right)

Если разница больше 1, левое поддерево слишком высокое.
Если меньше -1, правое поддерево слишком высокое.
Для восстановления баланса используются повороты влево и вправо. Иногда достаточно одного поворота, иногда сначала нужно повернуть дочернее поддерево.
Поиск работает как в обычном бинарном дереве поиска.
Сравниваем искомое значение с текущим узлом. Если они равны, возвращаем True. Если искомое значение меньше, идём влево, иначе вправо. Если дошли до пустого места, возвращаем False.
Удаление тоже выполняется по правилам BST.
Сначала находим нужный узел.
Если у него нет детей, просто удаляем его.

Если есть только один ребёнок, ставим этого ребёнка на место удаляемого узла.
Если есть два ребёнка, берём минимальный элемент из правого поддерева, заменяем им значение удаляемого узла, а затем удаляем этот элемент из правого поддерева.
После удаления при возвращении из рекурсии пересчитываем высоты и восстанавливаем баланс поворотами.
Для просмотра значений добавлен inorder-обход. Он выводит элементы AVL-дерева в порядке возрастания.


Оценка сложности:
Пусть n — количество узлов дерева.
AVL-дерево сохраняет высоту порядка O(log n), так как высоты поддеревьев в каждом узле отличаются не более чем на 1.
Поиск занимает O(log n) времени, потому что на каждом шаге переходим только в одно поддерево.
Вставка занимает O(log n) времени. Мы проходим один путь от корня до нового узла, затем обновляем высоты и выполняем повороты. Каждый поворот занимает O(1).
Удаление занимает O(log n) времени. Мы находим узел, при необходимости находим минимальное значение в правом поддереве и восстанавливаем баланс на пути обратно.
Дополнительная память поиска — O(1), потому что поиск сделан без рекурсии.
Дополнительная память вставки и удаления — O(log n), потому что используются рекурсивные вызовы, глубина которых ограничена высотой дерева.
Само дерево хранит n узлов, поэтому на хранение данных нужно O(n) памяти.
Inorder-обход занимает O(n) времени и O(n) памяти для списка результата.


Визуализация работы алгоритма:

Пример 1. Правый поворот.
Вставляем 30, затем 20, затем 10.

Получаем:

        30
       /
      20
     /
    10

У узла 30 левое поддерево слишком высокое.

Делаем поворот вправо:

       20
      /  \
     10   30

Теперь разница высот у всех узлов не превышает 1.


Пример 2. Левый поворот.

Вставляем 10, затем 20, затем 30.

Получаем:

    10
      \
       20
         \
          30

Делаем поворот влево:

       20
      /  \
     10   30


Пример 3. Двойной поворот.

Вставляем 30, затем 10, затем 20.

Получаем:

       30
      /
     10
       \
        20

Сначала поворачиваем поддерево узла 10 влево:

       30
      /
     20
    /
   10

Потом поворачиваем узел 30 вправо:

       20
      /  \
     10   30

Для противоположной ситуации используется сначала поворот вправо, затем влево.


Пример 4. Удаление и восстановление баланса.

Вставляем 4, 2, 5, 1, 3.

Получаем:

        4
       / \
      2   5
     / \
    1   3

Удаляем 5:

        4
       /
      2
     / \
    1   3

Теперь левое поддерево корня имеет высоту 2, а правое пустое.

Разница высот равна 2, поэтому делаем правый поворот:

       2
      / \
     1   4
        /
       3

Дерево снова сбалансировано.

Результат inorder-обхода:

[1, 2, 3, 4]


Тесты:

Проверяются следующие случаи:
пустое дерево и поиск отсутствующего значения;
вставка и поиск нескольких элементов;
дерево из одного узла и его удаление;
повторная вставка одинаковых значений;
обычный правый поворот;
обычный левый поворот;
двойной поворот влево-вправо;
двойной поворот вправо-влево;
удаление листа;
удаление узла с одним ребёнком;
удаление узла с двумя детьми;
удаление значения, которого нет в дереве;
восстановление баланса после удаления;
отрицательные числа и ноль;
вставка 100 значений по порядку;
последовательное удаление половины из 100 значений;
удаление всех элементов дерева.
В тестах также проверяются порядок значений, правильность высот узлов и балансировка всех поддеревьев.
